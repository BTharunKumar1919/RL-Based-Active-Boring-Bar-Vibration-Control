# Active Vibration Control of a Rotary Boring Bar

Simulation-only project comparing **No Control**, **PID**, and **Soft Actor-Critic (SAC)** for a seven-mode rotary boring-bar model. The project includes a modal plant, actuator dynamics, cutting-force disturbance models, reproducible experiments, a FastAPI service, and a Streamlit dashboard. It does not connect to physical machinery.

## Current model

The modal plant implements the paper-based transfer-function structure

\[
y(s)=G_{yI}(s)I(s)+G_{yF}(s)F_c(s)
\]

with six current-driven modes and one cutting-force-driven mode. The actuator path includes a first-order bandwidth model, current slew-rate limit, and current saturation. Integration of modal dynamics uses RK4 with the actual actuator current and cutting force held over each physical step.

The nominal configuration is in `config.py`. It uses a 0.1 ms plant time step, a 5 A continuous current limit, and the six current-driven modes and force-driven mode specified there. These values and the noise/preset ranges are model assumptions unless independently validated against measured hardware.

The SAC observation remains a history of 8 samples of normalized displacement, velocity, and actual actuator current (24 input values); the action is normalized commanded current. This preserves compatibility with the bundled 7-mode checkpoint. The policy does not directly observe plant identity or cutting-force model identity, so testing on a different plant or disturbance is a generalization test, not guaranteed transfer.

## Features

- Original controller-comparison workflow: No Control, PID, and SAC.
- Configurable plant presets plus per-mode percentage changes for modal frequency, damping, and current-input gain; the force-driven mode also exposes stiffness.
- Cutting-force models: single harmonic, multi-harmonic, amplitude-modulated, and combined harmonics/modulation.
- Independent cutting-force noise, additive process-force noise, and displacement sensor noise.
- Individual SAC training and generalized training across randomized plant modal parameters and randomized fundamental force conditions.
- Background SAC training jobs with progress, logs, and cancellation. Cancellation saves a partial checkpoint and registers it as interrupted; it should not be treated as converged.
- Policy registry records the checkpoint path and training configuration. Evaluation on a different configuration is allowed and warns about mismatch.
- CSV export, response plots, and controller metrics.

## Run the app

Start the API in one terminal:

```bat
.venv\Scripts\python.exe -m uvicorn api:app --reload
```

Start the Streamlit dashboard in a second terminal:

```bat
.venv\Scripts\python.exe -m streamlit run app.py
```

The API defaults to `http://127.0.0.1:8000`; its interactive documentation is at `http://127.0.0.1:8000/docs`. The Streamlit sidebar allows changing the API URL.

The original dashboard flow is retained. The **Configurable experiments and SAC policy registry** section provides the expanded workflow:

1. Select a controller and, for SAC, a registered checkpoint.
2. Select a plant preset, then adjust each mode's parameters.
3. Choose a cutting-force family and configure harmonics, modulation, and noise.
4. Configure independent process and sensor noise, simulation duration, and seed.
5. Run the experiment and inspect metrics, displacement trace, and downloadable CSV.
6. Open **Train and manage SAC policies** to train an individual or generalized policy, inspect job progress/logs, or request cancellation.

## Plant presets and parameter offsets

- `paper_nominal`: baseline plant parameters from `config.py`.
- `frequencies_minus_5pct`: all modal frequencies shifted by −5%.
- `frequencies_plus_5pct`: all modal frequencies shifted by +5%.
- `reduced_damping_10pct`: all modal damping ratios shifted by −10%.

Per-mode GUI values are percentage-point offsets added to the selected preset. Zero leaves the preset unchanged. Current-driven modes expose frequency, damping, and input-gain offsets; the force-driven mode exposes frequency, damping, and stiffness offsets. Invalid modal values are rejected.

These presets are experiment conveniences, not validated uncertainty bounds. Offsets are constrained in the GUI to ±20% per editable parameter; the generalized-training randomization range is separately configurable up to ±30%.

## Cutting-force and noise semantics

- **Single harmonic:** one sinusoid.
- **Multi-harmonic:** fundamental plus configured harmonic components.
- **Amplitude-modulated:** fundamental multiplied by a periodic amplitude envelope.
- **Mixed:** harmonics plus amplitude modulation.
- **Cutting-force noise:** additive random force at the disturbance source.
- **Process noise:** independent additive random force applied to the force-driven modal equation.
- **Sensor noise:** additive noise on the displacement measurement presented to the controller. Velocity remains the simulated state velocity; this is not a complete sensor/estimator model.

Noise standard deviations are in N for force/process noise and metres internally for displacement sensor noise (the GUI accepts micrometres). All stochastic experiments use an explicit seed.

## SAC training and registry

`POST /training/jobs` starts an in-process background job. `GET /training/jobs/{job_id}` returns status, progress, recent logs, and any error. `POST /training/jobs/{job_id}/cancel` requests a stop at the next SAC callback; the resulting checkpoint is marked as partial. Training jobs run in the API process, so stopping/restarting that process interrupts active jobs.

The registry is stored at `results/policy_registry.json`, and new checkpoint files go to `results/policies/`. The bundled `results/sac_vibration_model_7mode.zip` is listed automatically if present. Existing legacy checkpoints are not retroactively given detailed training metadata; compatibility warnings for these checkpoints are therefore approximate.

Individual training uses the selected plant configuration and force-model family. For the sinusoidal force model, episode amplitude/frequency/phase are randomized using the configured training ranges. Generalized training additionally randomizes modal frequency, damping, and gain/stiffness around the selected plant, and randomizes fundamental force amplitude/frequency/phase. Harmonic structure and modulation settings remain as configured. The policy observation/action shape is unchanged.

## Tests

From the project folder, run:

```bash
python -m pytest -q
```

The included tests check plant-config round-tripping, modal perturbations, preset/offset composition, seeded force reproducibility, and a short No Control experiment. They do not validate policy quality or physical fidelity.

## Limitations

This is a simplified simulation. The prescribed cutting-force profiles are not a regenerative chatter model, and no hardware connection, physical sensor calibration, or experimental validation is implemented here. Noise models and parameter ranges are configurable assumptions. PID gains may need retuning when plant parameters change. The generalized SAC policy may still perform poorly outside the training distribution; compare against PID and No Control and inspect multiple seeds before drawing conclusions.
